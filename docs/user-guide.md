# Руководство пользователя (AI Test Generator)

Добро пожаловать в приложение AI Test Generator! Это простое и удобное средство для превращения учебных материалов, регламентов и статей в готовые к прохождению тесты.

## 1. Загрузка документа и создание теста

1. На стартовой странице выберите пункт **"Загрузка"** в верхнем меню.
2. Подготовьте документ в формате **PDF** или **DOCX** (Word). Убедитесь, что файл весит не более 10 МБ и содержит не более 30 страниц текста.
   > **Важно**: Отсканированные PDF без текстового слоя (просто картинки) не поддерживаются.
3. Нажмите **"Выбрать файл"** или перетащите файл в область загрузки.
4. После отправки откроется экран **прогресса генерации**. Он показывает этапы обработки (`upload -> parse -> index -> generate -> done`) и текущий процент.
   - Также отображаются технические поля этапа: `stage` и время последнего обновления.
   - На странице **Загрузка** доступен debug-блок со статусом backend (`/api/health`) и последними логами (`/api/logs`).
5. По завершении вы будете автоматически перенаправлены на экран прохождения теста.

## 2. Прохождение теста

1. Перейдите в раздел **"Библиотека"** (через меню). Там отображается история всех сгенерированных тестов.
2. Выберите нужный тест и нажмите **"Начать тест"**.
3. Вы будете последовательно отвечать на вопросы разных типов:
   - **Выбор ответа**: Выберите один правильный вариант из предложенных.
   - **Верно / Неверно**: Определите истинность утверждения.
   - **Открытый вопрос**: Введите развернутый ответ своими словами.
4. Перемещайтесь между вопросами с помощью кнопок **"Назад"**, **"Пропустить"** и **"Следующий"**.
5. На последнем вопросе кнопка **"Следующий"** превращается в **"Завершить"** и отправляет ответы на сервер.
6. В верхней части экрана теста доступен блок **"Диагностика генерации"** (если backend вернул данные): качество извлечения текста, метод парсинга и метрики генерации (`generationMetrics`).

## 3. Просмотр результатов

1. После завершения теста вы будете автоматически перенаправлены на страницу ваших результатов.
2. Вы увидите свой общий процент успеха и балл.
   - Для восстановленного итога (если страница перезагружена) показывается время завершения последней попытки из истории (`completed_at`).
3. Ниже будет расположен подробный разбор: ваш ответ, правильный ответ (от ИИ) и краткое **объяснение**, почему этот ответ верен, основанное на тексте исходного документа.
4. Для детального анализа нажмите **"Подробный разбор"** — откроется покомпонентный разбор по каждому вопросу.
5. Из библиотеки вы также можете скачать тест в JSON кнопкой загрузки. Такой файл содержит вопросы, варианты ответов, подсказки (`hint`), правильные ответы (`correct_answer` / `correctIndex`) и объяснения.
6. На странице прохождения теста доступна кнопка **"Скачать JSON"** — она выгружает тот же полный формат для текущего теста.
7. В библиотеке можно выбрать режим сортировки: ручной порядок, сначала новые, сначала старые или по названию.
8. В режиме **"ручной порядок"** используйте стрелки вверх/вниз на карточке, чтобы поменять позицию теста в списке.
9. Из библиотеки вы также можете удалить тест кнопкой с иконкой корзины.

## 4. Почему в Manual только 3 модели

На странице **Загрузка** список в блоке **"Модель для всех этапов"** берется из реестра моделей в БД (endpoint `/api/models`), то есть из тех моделей, которые включены в админке.

Если в выпадающем списке мало моделей, обычно причина в одном из пунктов:
- модель не синхронизирована в реестр;
- модель выключена в **`/admin/ai/models`**;
- у модели нет корректного `api_model_id`;
- backend временно перешел в fallback на статический конфиг (при ошибке доступа к реестру).

Это сделано специально:
- чтобы не показывать неподходящие/дорогие/preview-модели обычному пользователю;
- чтобы контролировать квоты и стабильность генерации.

Если нужно больше моделей в Manual-списке — сначала включите их в **`/admin/ai/models`**.

## 5. Как настроить кастомный тариф и выбор модели по ролям (админ)

Ниже — практический сценарий "своими руками", без кода.

### Шаг 1. Проверьте, что нужные модели включены

1. Откройте **`/admin/ai/models`** (раздел *Модели ИИ*).
2. Нажмите **"Синхронизировать"** — подтянется актуальный список из провайдера.
3. Убедитесь, что у нужных моделей переключатель **"вкл"** активен.

Если модель выключена здесь, роутер не сможет выбрать ее в тарифах/ролях.

### Шаг 2. Настройте тарифные правила (fallback-логика)

1. Откройте **`/admin/ai/tariffs`** (раздел *Тарифы ИИ*).
2. Для каждого этапа и профиля (Economy / Standard / Premium) задайте:
   - **Fallback модель**;
   - **Действие при лимите** (`fallback_model` / `skip` / `fail_fast` / `queue`).
3. Нажмите **"Сохранить"** у измененной ячейки.
4. Внизу используйте **"Песочницу роутера"**, чтобы проверить результат до реальной генерации.

Этот экран отвечает за стратегию поведения при ограничениях и запасные варианты.

### Шаг 3. Назначьте модель по роли и stage

1. Откройте **`/admin/ai/routing`** (матрица *Роли и этапы*).
2. Для каждой строки (stage) задайте:
   - **Primary** (основная модель),
   - **Fallback** (резерв),
   - флаги **Premium** / **Preview**.
3. Нажмите **"Сохранить"** по строке.
4. Сравните колонки:
   - **Configured** — что вы явно настроили;
   - **Effective now** — что реально выберет система сейчас с учетом квот и политик.

Именно этот экран нужен, если хотите "для конкретной роли -> конкретную модель".

### Шаг 4. Политики и ограничения premium

1. Откройте **`/admin/ai/policies`**.
2. Настройте:
   - `premium_guard_enabled`,
   - мягкий/жесткий порог premium,
   - emergency downgrade и другие глобальные флаги.

Если видите высокий счетчик `Premium Guard`, можно:
- временно отключить premium на тяжелых stage в `routing`,
- или ужесточить политику premium в `policies`.

### Шаг 5. Проверка результата

1. Запустите тестовую генерацию.
2. Посмотрите:
   - **`/admin/ai/debug`** — как принималось решение по модели;
   - **`/admin/ai/usage`** и **`/admin/ai/home`** — эффект на расход/блокировки.

Если `Effective now` и фактические решения совпадают, настройка сделана корректно.

## 6. Новый раздел "Режимы ИИ" (admin)

Для сложных сценариев используйте отдельный слой профилей режима:
`/admin/ai/modes`.

### Быстрый workflow
1. Откройте **`/admin/ai/modes`** и нажмите **"Клонировать"** у `quality` или другого профиля.
2. Перейдите в **конструктор режима** (`/admin/ai/modes/:id`) и настройте:
   - global flags (`allowPremium`, `allowPreview`, `stableOnly`, `emergencyFallback`);
   - назначения по `mission/stage/role`;
   - `primary_model_id` и `fallback_model_ids`.
3. Нажмите **Validate** — появится блок **Configured vs Effective Preview**:
   - что настроено;
   - что реально сработает;
   - где сработали блокировки (`health`, `premium_guard`, `preview_guard`, `emergency_downgrade`).
4. На странице **`/admin/ai/modes/:id/test`** выполните dry-run и test-run по `document_id`.
5. На странице **`/admin/ai/modes/:id/runs`** смотрите историю запусков выбранного режима.

### Импорт/экспорт
- Экспорт: кнопка **"Экспорт"** в списке режимов (`mode-<id>.json`).
- Импорт: кнопка **"Импорт JSON"** и вставка JSON-конфига.

### Важно
- Системные режимы (`is_system=true`) нельзя редактировать.
- Custom mode не заменяет manual override, а работает как отдельный конфиг-профиль.
- Даже при ручном выборе модели effective-план может измениться из-за guard-ограничений.
